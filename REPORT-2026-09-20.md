It does block the frontend port and MCP server (next sprints).

**Ambiguities decided (all flagged in §5):**

1. **`onRevoke`: spec says `return false`, brief says revert.** Followed the spec. Both produce a revert at the EAS level (`InvalidRevocation()`), and EAS core rejects revocation on a non-revocable schema before the resolver is even reached; the fork tests prove both layers.
2. **Object resolver and `originUid`.** Spec is silent → the resolver validates nothing about it (authenticity only; origin resolution is indexer rule O-1). Tested explicitly that `originUid` may be zero, equal to `refUID`, or point nowhere.
3. **`transferId` hardening (deviation from spec text).** The fuzzer found that with `msg.sender == address(0)` the spec's single check `idToWallet[id] == msg.sender` passes for any *unissued* ID, letting the zero address "transfer" it to an arbitrary wallet and corrupt the bijection. A real sender can never be `address(0)`, but the contract is immutable and ETHSkills security says to reject zero/out-of-bounds inputs, so I added `owner != address(0) &&` to the check. Error string unchanged, gas +~100 on a rare call. Nate to ratify.
4. **Revert strings kept verbatim from the spec** (not custom errors). Gas-cheaper custom errors only matter on revert paths and would change what the SDK matches on. Nate's call before mainnet since it is permanent.
5. **Optimizer runs = 10 000**, EVM `cancun`, Solidity `0.8.26` (spec pin). Deployment cost is a few cents either way.

**Important finding: the two chains run different EAS versions.** Base mainnet EAS is `1.0.1`; Base Sepolia EAS is `1.2.0` (both at the `0x4200…0021` predeploy; verified with `cast call … "version()"`). The delegated-attestation EIP-712 typed data differs:

- 1.0.1: `Attest(bytes32 schema,address recipient,uint64 expirationTime,bool revocable,bytes32 refUID,bytes data,uint256 nonce)`; request struct has no `deadline`.
- 1.2.0: `Attest(bytes32 schema,address recipient,uint64 expirationTime,bool revocable,bytes32 refUID,bytes data,uint256 value,uint256 nonce,uint64 deadline)`; request struct has `deadline`.
- Neither matches the current eas-contracts library (1.3+ prefixes `address attester`).

The resolvers are unaffected (they see the same `Attestation` struct), and the fork tests contain working encoders for both. But the **SDK/relayer must build chain-specific typed data**, and a Sepolia dry-run does not exercise the mainnet delegated encoding — the mainnet fork test does.

## 5. Open questions for Nate

1. **"Proposal" vs "scope of work" (Sep 16 call with Ting).** Confirmed: **no contract change.** The contracts never decode `metadata`; both are just `metadata.type` values on Object attestations. This belongs in the (missing) EAS schema spec's type vocabulary and in indexer rules. Test `test_Subject_MetadataNeverInterpreted` / `testFuzz_MetadataContentNeverAffectsOutcome` pin this.
2. **Milestones must not be immutable onchain.** Confirmed satisfied, with a nuance: there is **no milestone state in any contract**. A milestone is an Object; its *current state* is derived by "latest authoritative update wins" (indexer U-1/U-2), so state is freely updatable. What *is* immutable is the history — every prior version stays visible and non-revocable. If Ting's requirement is "history must be erasable", that is *not* satisfied and is a deliberate v2.1 decision (non-revocable schemas); worth confirming which meaning was meant.
3. **`ottp-eas-schema-spec.md` v2.1 must be written** before the frontend/MCP sprint. Not blocking mainnet for contracts. The schema UID tables it should hold come from the deploy output.
4. **Ratify the `transferId` hardening** (§1 item 3). Trivial, safer, same error string; but it is a textual deviation from a ratified spec.
5. **`onRevoke` returns `false` (spec) vs reverts (brief).** Kept spec. Equivalent at the EAS boundary; say if you want an explicit revert for readability.
6. **Object resolver: validate anything about `originUid`?** Currently nothing (spec silent, authenticity-only principle). Recommend leaving it; the indexer's O-1 handles dangling/foreign origins and any contract rule here would foreclose client-invented uses.
7. **Revert strings vs custom errors.** Kept spec strings. Decide before mainnet — it is permanent.
8. **Exact schema strings** are permanent inputs to the schema UID: `uint256 ottpId, string name, string metadata` and `bytes32 originUid, uint256 creatorId, string metadata` (comma-space, as in the spec). Confirm before mainnet.
9. **Two EAS versions on Base** (§3.2). The SDK/relayer needs per-chain delegated typed data. Consider using the EAS SDK's version detection rather than hand-rolling.
10. **Verification pipeline untested** (no Basescan key). `foundry.toml` is configured for the Etherscan v2 API; first Sepolia deploy should confirm `--verify` works.
11. **Cosmetic:** `git status` shows `lib/openzeppelin-contracts` as "modified content" because OZ's own nested `lib/forge-std` submodule is uninitialised inside it. Our build uses the top-level forge-std; harmless, but `git submodule update --init --recursive` would clean the status.
12. **From the spec, outside this sprint but still undecided:** v1 UUPS proxy-admin disposition (renounce vs archive loudly) and the Supabase RLS hygiene items in the consolidated context §5.
